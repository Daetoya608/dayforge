# Telegram-бот

aiogram 3, long polling (входящие порты не нужны). Состояния диалогов — FSM aiogram с хранилищем в SQLite, чтобы переживать рестарт.

## Доступ

Бот обрабатывает только апдейты от `OWNER_TELEGRAM_ID` в личном чате. Всё остальное игнорируется (запись в лог без содержимого).

## Команды

| Команда | Действие |
|---|---|
| `/new` | Создать проект (диалог ниже) |
| `/projects` | Список проектов: метка, название, статус, день `4/10`, прогноз окончания, ⚠ открытые вопросы. Кнопка у каждого → `/status` |
| `/status <проект>` | Статус, текущий день и его задачи, незавершённое, последние коммиты, вехи. Кнопки: план, отчёт, пауза, `/next` |
| `/plan <проект>` | `PLAN.md` файлом + цели дней кратко |
| `/replan <проект> <что изменить>` | Перепланирование → diff на утверждение |
| `/calendar` | Календарь (см. ниже) |
| `/priority` | Список проектов с кнопками ↑ ↓ |
| `/pause <проект>`, `/resume <проект>` | |
| `/run [проект]` | `continue`: доделать незавершённое. Без аргумента — по всем проектам, где оно есть |
| `/next` | Выбор проектов галочками → «Начать» → `next` для выбранных |
| `/release <проект>` | Ручной релиз `dev` → `main` (с подтверждением) |
| `/report [проект]` | Последний отчёт |
| `/agent <текст>` | Сообщение системному агенту |
| `/agent_reset` | Новая чат-сессия системного агента |
| `/settings` | Часовой пояс, время запуска и бэкапа, агенты по умолчанию, таймауты, автопродолжение после лимита |

Где нужен `<проект>`, а он не указан — бот присылает кнопки выбора.

**Свободный текст** вне активного диалога и не reply на сообщение бота → системному агенту (как `/agent`).

## `/new`

1. **Идея** — свободный текст, можно несколькими сообщениями; кнопка «Готово».
2. **Стек** — текст или «Пусть выберет агент».
3. **Число дней** — число.
4. **Приоритет** — кнопки: «Первым», «Последним», «После <проект>».
5. **Агенты** — «По умолчанию» или выбор: агент → модель → reasoning, отдельно для планировщика и исполнителя.
6. **Дни недели** — переключатели Пн…Вс или «Настрою позже».
7. **Название и slug** — бот предлагает по идее, можно изменить.
8. Подтверждение → проект создан, планировщик запущен: «Агент изучает идею, скоро будут вопросы».

## Вопросы агентов

Каждый вопрос из `ask_user` — отдельное сообщение по очереди:

```
❓ todo-bot · T14 · вопрос 1 из 2
Задача T14 требует приёма платежей, в IDEA.md провайдер не указан.

Какую платёжную систему подключать?
[Stripe] [ЮKassa]
Или ответь на это сообщение текстом.
```

Ответ — кнопка или reply на сообщение. После последнего ответа:

```
✅ Ответы получены. todo-bot готов продолжить T14.
[▶ Продолжить сейчас] [Позже]
```

«Позже» — задача продолжится в ближайшем запуске проекта. Если идёт другой проект — «Продолжить сейчас» ставит в очередь и сообщает позицию.

Напоминание об открытом вопросе — при пропуске слота и не чаще `question_reminder_hours`.

## Секреты

```
🔑 todo-bot · T14 запрашивает STRIPE_API_KEY
Секретный ключ Stripe (test mode) для приёма платежей.
Где взять: Dashboard → Developers → API keys

Ответь на это сообщение значением. Сообщение со значением будет удалено.
```

Получив reply: значение → `.env` проекта, **сообщение пользователя удаляется** из чата, ответ: «🔑 Сохранено в `.env` как `STRIPE_API_KEY`» + кнопки продолжения. Значение нигде не логируется.

## Согласование плана

```
📐 todo-bot · план v1 на 10 дней
Telegram-бот для учёта расходов: FastAPI + aiogram + PostgreSQL
Вехи: M1 Базовый бот (дни 1–5), M2 Отчёты (дни 6–10)
Прогноз окончания: 13.11.2026
[PLAN.md] [ARCHITECTURE.md]
[✅ Утвердить] [✏ Правки] [✖ Отклонить]
```

- «Правки» → бот ждёт текст → он уходит в сессию планировщика.
- Предупреждения (другое число дней, не хватает дней в календаре) — над кнопками.
- Перепланирование — вместо плана diff ([plan-format.md](plan-format.md#diff)), сообщением или файлом, если длинный.

## Ожидающие действия

```
⚠ Подтверди действие системного агента
Удалить проект old-site (локальная копия и запись в системе; репозиторий на GitHub остаётся)
[Подтвердить] [Отмена]
```

Истекают через `pending_action_ttl_hours` — сообщение редактируется «⌛ истекло».

## `/calendar`

**Месяц:** inline-сетка 7×N, в ячейке — число и метки проектов (`badge`), использованные слоты — с точкой, общие выходные — 🚫, вычеркнутые — `~`. Кнопки ◀ ▶ по месяцам.

**Нажатие на дату** → список проектов с переключателями (✓/✗ на эту дату) и «Выходной для всех». Изменения сразу пересчитывают прогноз.

**Дополнительные экраны:** «Недельный шаблон» (таблица дни × проекты с переключателями), «Время запуска», «Прогнозы» (окончание по каждому проекту).

**«Назначить ещё дни»** из уведомления о нехватке — см. [calendar.md](calendar.md#нехватка-дней).

## Уведомления

| Событие | Кнопки |
|---|---|
| Ежедневный отчёт (по проекту) | Статус, план |
| Вопрос / запрос секрета | Варианты ответа |
| Ответы получены | Продолжить сейчас, Позже |
| План / diff на согласование | Утвердить, Правки, Отклонить |
| Предложение агента изменить план (`propose_plan_change`) | Передать планировщику, Отклонить |
| Задача не может быть выполнена (`fail_task`) | Передать планировщику, Вернуть в работу, Отменить задачу |
| Задача приостановлена (тесты, watchdog, ошибка) | Продолжить сейчас, Лог |
| Лимит подписки | Продолжить (после сброса) |
| Не хватает дней в календаре | Назначить ещё дни |
| Релиз вехи | Открыть на GitHub |
| Проект завершён | Открыть на GitHub |
| Ожидающее действие | Подтвердить, Отмена |
| Рестарт системы с прерванными задачами | Продолжить сейчас |
| Ошибка бэкапа | — |

## Ежедневный отчёт

Одно сообщение на проект после его запуска:

```
📋 todo-bot · день 4 из 10 · 14.10

✅ T9 Модель категорий
   Модель Category, миграция, 6 тестов
✅ T10 Команды /category
   add/list/remove, 12 тестов
   💡 Категории храню на пользователя, а не глобально
   💡 Удаление категории с расходами запрещено
⏸ T11 Импорт из CSV — ждёт ответа на вопрос

🧪 Тесты dev: зелёные · коммитов: 9 (abc1234…f00ba12)
🏷 Выпущено: v0.1.0
📅 Прогноз окончания: 13.11 (без изменений)
```

Текст задач (`summary`, `decisions` 💡) — от агента; остальное — факты системы. Ссылки ведут на коммиты, ветки и релизы на GitHub. Если в одном запуске несколько проектов — перед отчётами короткое сообщение-шапка: «Запуск 14.10: 3 проекта, 2 ✅, 1 ⏸».

## Длинные сообщения

Лимит Telegram — 4096 символов. Длиннее — отправляется файлом `.md` с кратким текстом в подписи.
