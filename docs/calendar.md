# Календарь

## Понятия

- **Слот** — дата, в которую проект должен работать.
- **День плана** — логическая единица плана (День 1, День 2, …). Дни плана не привязаны к датам.
- **Указатель дня** — `projects.current_day`, номер последнего начатого дня плана.

В каждый слот проекта выполняется **следующий** день плана (`current_day + 1`), плюс всё незавершённое перед ним.

## Правила слотов

Дата `D` — слот проекта `P`, если выполнено всё:

1. `P` в статусе `active` или `blocked` и `D ≥` даты утверждения плана.
2. Нет общего исключения: `calendar_dates(project_id = null, date = D, kind = exclude)`.
3. Одно из двух:
   - есть `calendar_dates(P, D, include)`, **или**
   - `weekday(D)` в `calendar_weekdays(P)` и нет `calendar_dates(P, D, exclude)`.

Явное `include` сильнее шаблона, проектное `exclude` сильнее шаблона, общее `exclude` сильнее всего.

**Использованный слот** — слот, на дату которого есть `runs(mode = scheduled, slot_date = D)` в любом статусе, кроме `cancelled`. Слоты не накапливаются: прошедший неиспользованный слот (проект на паузе, система лежала) просто пропадает.

## Ежедневный запуск

В `run_time` планировщик берёт все проекты, для которых сегодня — неиспользованный слот, и ставит их в очередь в порядке `priority` ([run-lifecycle.md](run-lifecycle.md#очередь)).

## Досрочный запуск (`/next`)

`/next` начинает следующий день плана сразу, не трогая календарь. Слоты — это даты, а не дни плана, поэтому:

- если сегодня у проекта ещё будет запуск по расписанию — он выполнит уже **следующий** день;
- проект просто проходит план быстрее, прогноз сдвигается на более раннюю дату;
- лишние слоты в конце освободятся при завершении.

## Прогноз окончания

```
осталось_начать = planned_days − current_day
если осталось_начать = 0:
    если есть незавершённые задачи → дата ближайшего неиспользованного слота
    иначе → проект завершён
иначе:
    дата k-го ближайшего неиспользованного слота, k = осталось_начать
```

Поиск слотов — от сегодняшнего дня (если сегодняшний слот ещё не использован) вперёд, на горизонте 365 дней. Прогноз пересчитывается при каждом изменении календаря, плана, после каждого запуска и показывается в `/projects`, `/status`, отчётах и шапке `PLAN.md`.

## Нехватка дней

Если на горизонте меньше слотов, чем `осталось_начать` (обычно — когда проекту отмечены только отдельные даты), система отправляет уведомление:

> Проекту **todo-bot** не хватает 3 дней в календаре. Прогноз окончания невозможен.
> [Назначить ещё дни]

Кнопка открывает выбор:

- **«+3 / +5 / +10 будней»** — добавить `include` на ближайшие рабочие дни (пн–пт), которые ещё не слоты проекта и не общие выходные;
- **«Выбрать в календаре»** — открыть календарь месяца: там же отмечаются отдельные даты и меняется недельный шаблон.

Проверка выполняется при утверждении плана, после изменения календаря или плана и после каждого запуска.

## Вычёркивание

Когда проект завершён (`completed`) или архивирован, его будущие слоты больше не вычисляются (п. 1 правил). В `/calendar` они показываются зачёркнутыми ещё 7 дней после завершения, чтобы было видно освободившееся время, затем исчезают. Данные (`calendar_weekdays`, `calendar_dates`) не удаляются — они нужны для истории.

## Пример

Шаблон: проект A — Пн, Ср, Пт; проект B — Вт, Чт. Общий выходной — 4 ноября. План A — 5 дней, утверждён в воскресенье 1 ноября 2026 года.

| Дата | Слот A | Что выполнено |
|---|:-:|---|
| Пн 2.11 | ✓ | День 1 |
| Вт 3.11 | | `/next` для A → День 2 досрочно |
| Ср 4.11 | — (общий выходной) | |
| Пт 6.11 | ✓ | День 3 |
| Пн 9.11 | ✓ | День 4 |
| Ср 11.11 | ✓ | День 5 → проект завершён |
| Пт 13.11 | ~~вычеркнут~~ | |

Без `/next` проект закончился бы в Пт 13.11.

## Интерфейс в боте

Подробно — в [telegram-bot.md](telegram-bot.md#calendar). Кратко: месячная сетка с метками проектов (`projects.badge`), нажатие на дату — переключение проектов на эту дату (`include`/`exclude`), отдельный экран недельного шаблона и общих выходных.
