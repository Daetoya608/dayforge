# Dayforge — правила для агентов, работающих с этим репозиторием

Dayforge — система на сервере, где AI-агенты (Claude Code, Codex) разрабатывают проекты пользователя по ежедневному плану; управление — Telegram-бот. Один пользователь-владелец.

## Что читать

1. [README.ru.md](README.ru.md) — что делает система и почему так (решения, согласованные с пользователем).
2. [docs/development.md](docs/development.md) — **как устроен код и как его менять**: карта модулей, потоки, тесты, рецепты, грабли.
3. [docs/](docs/README.md) — спецификация по темам (архитектура, модель данных, план, запуски, календарь, git, агенты, MCP, бот, эксплуатация). Это источник истины: при изменении поведения обновляй соответствующий документ в том же коммите.

Документация — на русском (README — на двух языках, держать их синхронными). Комментарии и docstring в коде — на русском, имена — на английском.

## Команды

```bash
make install      # зависимости (uv)
make check        # ruff + pytest — обязательно перед каждым коммитом
make fmt          # форматирование
make run          # локальный запуск (откажется, если работает серверный бот)
make sync         # синхронизировать ветку dev на сервер и перезапустить службу
make status / logs / logs-follow / sessions / session-log ID=…   # сервер
make start / stop / restart                                       # служба на сервере
```

Без `make`: `uv run pytest -q`, `uv run ruff check . && uv run ruff format --check .`, `deploy/deploy.sh root@<адрес>`.

## Правила

- **Ветка `dev`, один коммит на законченную задачу.** Conventional Commits (`feat(core): …`, `fix(runner): …`), тело — что и почему. В `main` не мержить и не пушить на GitHub без просьбы пользователя.
- **Перед коммитом — `make check` зелёный.** Изменил модели БД — `uv run alembic revision --autogenerate -m "…"` (тест `test_migrations_match_models` упадёт, если забыть).
- **`.env` содержит настоящие токены** — никогда не выводи его значения (ни в чат, ни в лог). Проверяй только наличие ключей.
- **Не запускай локальный бот, пока работает серверный** — оба опрашивают один токен Telegram.
- **Сервер** (`root@82.25.58.76`, служба `dayforge`) — синхронизируй через `make sync` только закоммиченное и только когда не идёт сессия агента (`make status` → «процессов агентов: 0»), иначе перезапуск прервёт задачу.
- Флаги CLI агентов упоминаются только в `dayforge/agents/claude_code.py` и `codex.py`; при обновлении CLI сверяй их по `--help` и живым прогоном (см. docs/development.md).
